## 3. 🟠 HIGH (요약)

- **스코프:** 해제할 때 부모의 `owned_children`에서 빠지지 않아서 `<if>` 토글마다 목록이 커집니다. Effect 안에서 만든 Effect도 소유되지 않습니다. `unmount`의 `_effects.clear()`는 아무 효과가 없습니다(`Effect`가 `Copy`라서).
- **IME/키 입력:**
  - KeyEvent.text와 Commit 중복 제거를 "마지막 문자열 비교"로 해서, `ll`처럼 같은 글자를 연속 입력하면 두 번째가 사라집니다.
  - `ctrl_pressed`에 AltGr이 포함돼 독일어·폴란드어 배열에서 `@`가 입력되지 않습니다.
  - Esc를 누르면 앱이 종료되고, 숫자 1~4가 테마를 바꿉니다(프레임워크가 앱 단축키를 가로챔).
  - 캐럿 위치 계산이 두 곳에서 서로 다른 공식으로 중복돼 있습니다.
- **렌더러:**
  - 아틀라스가 RGBA이고 키가 픽셀 해시이며, 가득 차면 프레임 중간에 초기화합니다.
  - 텍스트 캐시는 이름만 LRU이고 실제로는 FIFO입니다. `char_x_offsets`가 O(n²)입니다.
  - 글꼴이 없으면 회색 박스를 글리프인 척 그립니다(가짜 폴백). 감마 `powf(0.80)` 같은 HiDPI 땜질이 있고, tiny-skia는 DPI를 무시합니다.
  - `framebuffer_rgba`가 여전히 0으로 채운 가짜 버퍼를 반환합니다.
- **레이아웃 / 히트테스트:**
  - 노드를 unmount할 때 Taffy 노드를 지우지 않아 누수가 생깁니다.
  - 히트테스트가 슬랩(slab) 역순이라 페인트 순서와 다를 수 있고, 클리핑과 상태 transform도 무시합니다.
- **컴파일러:**
  - `each="{(i, x) in v}"`에서 프록 매크로가 패닉합니다(`codegen.rs:164`).
  - `<style>` 블록 안에서 `{x}`를 쓰면 CSS 파서가 깨집니다.
  - CSS 에러 위치가 여러 CSS를 이어 붙인 결과 기준이라 틀립니다.
  - `id="row-{item.id}"`가 문자열 그대로 들어갑니다.
  - 미리보기가 컴파일 에러를 조용히 삼킵니다.
- **사용자 코드에 `Rc<dyn Fn>`:** 모든 예제의 `on_canvas_draw` 필드에 그대로 보입니다(AGENTS §2 위반).

## 5. 모바일 IME 리서치 요약 (unsafe 최소화 관점)

> [!IMPORTANT]
> winit은 **Android에서 IME 조합 이벤트를 전달하지 않고**(0.30 기준), **iOS에서는 marked text(UITextInput)를 지원하지 않습니다.** 이걸 해결하지 않으면 모바일에서 한글이 자모 단위로 깨집니다. egui, Bevy, Dioxus-native 같은 winit 기반 프레임워크가 공통으로 가진 문제입니다.

| 방법 | 우리 코드의 unsafe | 한국어 품질 | 비고 |
|---|---|---|---|
| Android `android-activity` GameActivity + GameTextInput | 0줄 | ⚠️ 삼성 키보드 조합 문제 보고 있음, 후보창 위치 API 없음 | 시작은 쉽지만 품질 위험 |
| **Android Kotlin `InputConnection` shim + `jni` pull 방식** | **약 2줄**(raw VM/Activity 포인터 변환), 별도 `*-sys` 크레이트에 격리 | ✅ Flutter·Slint와 같은 방식 | **추천** |
| Android Kotlin shim + UniFFI | **직접 쓰는 unsafe 0줄**(생성 코드의 `no_mangle`만 별도 `*-ffi` 크레이트에) | ✅ | 빌드 도구가 조금 더 무거움 |
| **iOS Swift `UITextInput` 뷰 + UniFFI / swift-bridge** | **직접 쓰는 unsafe 0줄**(`*-ffi` 격리) | ✅ Flutter 방식 | **추천** |
| iOS objc2 `define_class!`로 직접 구현 | `unsafe(method)` 약 30개 | ✅ | 비추천 |

- **결론:** `krui-core`는 `forbid(unsafe)`를 유지하고 플랫폼 중립 `EditingState` + `ImeEvent` + `TextInputHost` 트레이트만 가집니다. 플랫폼 연결은 별도 크레이트로 하고, **unsafe는 `*-sys`/`*-ffi` 크레이트에만, 직접 쓰는 것은 몇 줄 이내로 문서화**합니다.
- **데스크탑:** winit 0.31에 `request_ime_update`(캐럿·주변 텍스트·힌트를 한 번에 보내는 API)와 `DeleteSurrounding`이 추가됩니다. macOS에는 한글 첫 자모가 `insertText`로 오는 버그가 있습니다. 그래서 winit 동작에 기대지 말고 **core의 IME 상태 기계 하나에 OS별 시나리오 테스트**를 붙여야 합니다.
- 리서치 도구가 1차 출처를 직접 열지 못한 항목이 있습니다. 설계를 확정하기 전에 해당 크레이트 소스로 다시 확인이 필요합니다(작업 지시서에 포함).
