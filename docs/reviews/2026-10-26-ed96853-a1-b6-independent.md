# KRui A1~B6 독립 코드 리뷰 (2026-10-26, HEAD `ed96853`)

> 대상: 현재 HEAD `ed968538447d5ac31a6456e58f72f09458bbaa8a` (`B6`). 기존 문서의 기준선 `a76d8f8` 이후에 커밋된 A8과 B1~B6도 함께 검토했다.
>
> 방법: core·IME, compiler·preview, renderer·layout, winit·CLI·probe 영역을 병렬 정적 검토하고 Critical/High 후보는 원본 코드에서 다시 확인했다. 저장소 쓰기 범위 제한을 지키기 위해 cargo 빌드, 테스트, benchmark, probe는 실행하지 않았다. 따라서 아래 "통과"는 실행 합격이 아니라 코드와 테스트 존재 여부에 대한 정적 판정이다.

## 총평

A1의 CSS 토큰 원칙, A3의 명시적 Scope 소유, A5의 R8 atlas/LRU, A6의 Taffy 정리와 일반 hit-test, B2의 preview registry, B3의 versioned IR 등 실제로 구현된 구조는 확인됐다. 그러나 IME 텍스트 손상, preview 평가 패닉과 비원자적 remount, TCP 프레임 손상, 잘못된 기본 serve 경로처럼 제품 핵심 목표를 직접 위반하는 결함이 남아 있다.

**현재 HEAD는 A1~B6 독립 검증 기준에서 불합격이다. 새 기능 단계로 진행하기 전에 Critical/High 수정과 회귀 테스트가 필요하다.** 기존 probe 통과 기록은 A7 시점이며 B6 현재 코드나 아래 실패 경로를 증명하지 않는다.

## 검증 범위와 한계

- 실행하지 않음: `cargo fmt`, clippy, workspace test, release benchmark, headless examples, `probe_krui.ps1`.
- 이유: 이번 리뷰 역할의 쓰기 허용 범위는 `docs/reviews/`와 `docs/TODO.md`뿐이며, cargo/probe는 `target*` 산출물을 갱신한다.
- 성능 수치는 새로 측정하지 않았으며 기존 수치도 이번 판정의 근거로 사용하지 않았다.
- `docs/HANDOFF.md`와 `docs/HISTORY.md`는 HEAD를 A7로 기술하고 있어 실제 저장소와 다르다. 이번 역할의 쓰기 범위 밖이므로 수정하지 않았다.
- 작업 트리에 선존재한 `docs/SHIFT.md`, `docs/prompts.md` 삭제와 `docs/ReviewRule.md` 신규 상태는 보존했다.

- **[Critical] `crates/core/src/view_tree/text_edit.rs:245-299`, `crates/core/src/view_tree/mod.rs:489-500`, `crates/core/src/view_tree/preview_remount.rs:115-201` — 늦은 Commit 전까지 `ime_target`을 유지하지 못한다.**
  - 영향: input1에서 `Preedit("한")` 후 `set_focus_to_node(input2)` → `Preedit("")`를 전달할 때 `pending_blur_committed`가 없으면 pin이 해제되어 다음 `Commit("한")`이 input2에 들어간다. blur 직후 preview remount도 `ime_target`을 지우고 빈 preedit은 복원하지 않아 같은 손상이 발생한다. `Commit("")`은 closure가 `None`을 반환해 pin 정리도 수행하지 않는다.
  - 제안: 조합 대상의 수명을 Commit/Disabled까지 한 곳에서 관리하고, programmatic focus도 공통 focus-transition 경로를 사용하게 한다. remount snapshot에는 focus와 독립적으로 IME target identity를 보존하고, 모든 commit 반환 경로에서 정리 정책을 일관되게 적용한다.

## 테스트 제안

우선순위 순으로 다음 회귀 묶음을 추가해야 한다. 각 항목은 해당 기능이 망가지면 반드시 실패해야 한다.

1. **IME 종합:** programmatic focus + empty preedit, 변환된 late commit, 빈 commit, pending blur 중 preview reload, host sync 대상 일치.
2. **평가 parity:** `i64::MIN`, 0 나누기, overflow, signal arithmetic, type error, 논리 연산, 미등록 메서드의 macro/preview 성공·오류 일치.
3. **Transactional reload:** 모든 binding 종류와 inactive branch의 registry 오류에서 이전 tree, scope, focus, 반응성, `Reloaded` 미전송을 확인.
4. **TCP/UI:** fragmented/coalesced frame, partial write, slow peer, malformed length/payload 중에도 프레임과 입력이 유지되는지 확인.
5. **실제 serve E2E:** 실제 예제 기본 경로로 시작해 `.krui` 저장→1초 안에 상태 유지 reload, `.rs` 저장→rebuild/restart, 실패 exit code를 자식 process까지 실행해 확인.
6. **Device frame:** preset별 physical/logical viewport, safe-area, clipping, pointer 경계와 DPI를 픽셀·이벤트로 확인.
7. **렌더링:** transformed clip, wheel routing, 2x framebuffer, external DPI, caret→paint 순서, 작은 vertex/index limit를 확인.
8. **수명:** ROOT poller 완료, anchor 직접 unmount, 중첩 update, disposed fallback 수, `<if>`/`<for>` 각 1,000회 후 모든 runtime counter와 fallback 보존 수의 정확한 일치.
9. **CSS:** pseudo-class specificity, multi dynamic class, source order, inline, external variable cycle/undefined의 정확한 출처.
10. **Probe 자체:** 느린 p99, GPU 미사용, cargo tree 실패, 예제 프레임 부족을 주입했을 때 probe가 nonzero로 실패하는지 확인.

## 정적으로 확인된 정상 경로

- 모든 crate root에 `#![forbid(unsafe_code)]`가 있고 직접 작성한 `unsafe` 블록은 찾지 못했다.
- A1: core/renderer의 RGB 용도 추론은 제거됐고 preset과 사용자 token override 경로가 있다.
- A2: 일반 한글 click/Tab commit, 영어 `ll`, AltGr, unfocused Esc, 숫자키 중립, shared caret helper는 구현돼 있다.
- A3: `pending_mount_scope` 제거, Store-after-session 생존, `owned_children` 정리, nested Effect 정리, poller 재진입 borrow 해소, transition의 zero-tolerance counter 비교는 확인했다.
- A5/A6: R8 atlas, frame-boundary overflow 처리, color-independent mask, 실제 LRU, hollow `.notdef`, `powf` 감마 제거, Taffy 제거, 일반 paint-order hit-test는 확인했다.
- A7: malformed `each`, style braces, 중복/미지원 속성, 잘못된 `type`/`selectable`, entity 순서, unbraced event에 대한 명시적 오류가 있다.
- A8: core의 patterns/winit/wgpu 분리, `Backends::all`, external device/view API, `CanvasDraw`, 최소 창 크기 제거, 공유 window loop는 확인했다.
- B1~B4: AST 문법 제한, preview registry 생성, versioned binary codec, 모든 선언된 IR node/binding을 다루는 interpreter, happy-path PaintScene parity와 100 reload counter 테스트는 존재한다.
- B6: nominal TCP reload, compile-error overlay에서 기존 UI 유지, restart, inspect, overlay 명령 테스트는 있다. 단, 이 테스트들은 위 실패 경로와 실제 CLI E2E를 커버하지 않는다.
